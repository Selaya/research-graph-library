Sequence diagram basics — a login round trip, unfolding as the ball travels

A sequence diagram drawn with the library's custom-solver seam: each actor is declared container: true and becomes a lifeline column, each activation is a child that carries its own (actor, time) placement in data.seq for demo/sequence-solver.js to read, and every message is an edge the run token rides — app → gateway → auth → database and back. Each edge declares its own data.duration, so the cellular hop to the gateway takes visibly longer than the calls inside the datacentre. The diagram grows one activation ahead of the ball, so you read it the way it happens.

    What to look for

    • The ball is one request: it leaves the app, dwells on every activation it reaches, and comes back with the response.
    • Each actor is declared container: true, so it draws as a dashed header box before its first activation and grows into a lifeline column as children are added.
    • Message labels ride the edges on their own backing pill; activation labels say what the actor does while the ball is there.
    • Wire time is per edge: the mobile ⇄ gateway hops are long, the calls between gateway, auth and the database are nearly instant.
    • The second request is shorter: the gateway verifies the JWT locally and never calls the auth service.
    • Scrub the transport bar backwards: structural steps are snapshotted, so the diagram folds back up.
