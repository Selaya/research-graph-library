Sequence diagram basics — a login round trip, unfolding as the ball travels

A sequence diagram drawn with the library's custom-solver seam: each actor is a container that becomes a lifeline column, each activation is a child placed on a (actor, time) grid by demo/sequence-solver.js, and every message is an edge the run token rides — app → gateway → auth → database and back. The diagram grows one activation ahead of the ball, so you read it the way it happens.

    What to look for

    • The ball is one request: it leaves the app, dwells on every activation it reaches, and comes back with the response.
    • Each actor column is a normal container node — the solver just stacks its children by row, so the lifeline grows as activations are added.
    • Message labels ride the edges; activation labels say what the actor does while the ball is there.
    • The second request is shorter: the gateway verifies the JWT locally and never calls the auth service.
    • Scrub the transport bar backwards: structural steps are snapshotted, so the diagram folds back up.
