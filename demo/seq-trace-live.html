What to look for

  • Click any activation — including a resume — to read the span behind it; the inspector bar shows where that span sits inside the 1 322 ms request.
  • Rows are trace order. reserveStock and GET /v2/quote share a row because orders-svc fanned out to both at once — one finish(), two tokens.
  • pricing-svc answers 500: run.fail() consumes that token and fans out nothing, so the branch simply dies mid-diagram.
  • orders-svc handles it with a fallback span — an explicit start(), the only thing that gets a token back after a failure. It is a leaf: nothing leaves it.
  • Each postgres statement is a nested span on the same lifeline, so the ball stays in that column until COMMIT returns.
  • At the end the view clock scrubs back to the 500 while the frontier keeps running — then follow() snaps it to now.
