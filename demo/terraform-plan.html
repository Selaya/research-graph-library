Terraform plan / apply — a resource-dependency DAG, plus a caught cycle

vpc fans out to two subnets and a security group; rds and eks-cluster each wait on all three (an AND-join) before creating; the cluster then unblocks a node group and an IAM role, and both must finish before app-deployment. The node group's first create call comes back InsufficientInstanceCapacity and the apply retries it — a declared failure with a retry budget, riding its own onFail arc. Then a change request adds a dns-record depending on the deployment — and someone also wires the deployment back onto the record, a circular dependency Terraform would refuse to plan. The graph renders it anyway, as a back edge, calls it out, then the bad edge is removed and the apply replays clean.
