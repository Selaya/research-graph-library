LLM evaluation harness — a prompt eval run that fails, retries, and passes

A candidate prompt set fans out to 6 held-out test cases; each case's model output is scored by its own LLM judge; the six verdicts join:"all" into a score aggregation step that hands its scorecard to Revise prompt and then to a threshold gate. The gate's check fails — two cases score badly, and pass@1 lands under the 0.80 bar — so it takes its declared retry budget (data.fail: { retries } on an onFail loop edge): every attempt flies the dashed arc back to Revise prompt, re-runs it, and re-checks the gate, with the iteration badge ticking for real. The budget runs out red; a human then rewrites the two weak cases, the story recompiles the run ({ op: "run" }), and prompt v2 clears the bar.

  • 6 test cases fan out from Prompt set into the cases container, each at its own generation latency; each case feeds its own child judge inside the judges container.
  • Score aggregation is an implicit AND-join of all 6 judges; its scorecard goes to Revise prompt and on to Threshold gate, which declares data.fail: { reason, retries: 2 } with the exact reason ("pass@1 = 0.62 < 0.80").
  • The dashed arc is that failure's retry arc — loop: true, onFail: true. Each non-terminal fail flies it back to Revise prompt, re-runs that step and re-checks the gate; state().loops.retry drives the iteration badge, and 'failed' only sticks on the attempt that finds the budget spent.
  • The two weak cases get a warn highlight + a red --smv-fill props tint so you can spot exactly what dragged the average down. Status tint composes with the role colour, so a red-scored node still reads as failed.
  • Prompt v2 rewrites those two cases, drops the gate's fail with update(..., { replace: true }), and the story recompiles the run from a { op: "run" } step — a real second pass over the whole harness, ending with an ok-variant highlight on the gate.
