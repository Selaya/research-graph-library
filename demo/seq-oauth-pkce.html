OAuth authorization code + PKCE — a login, then a silent token refresh 55 minutes later

Same solver seam as the login walkthrough and the checkout detour: four lifelines, one activation per row, every message an edge the run token rides. The authorization code never travels straight from the identity provider to the app backend — it bounces through the browser, and PKCE's code_verifier/code_challenge pair is what stops a stolen code from being redeemed by anyone else. Later, the access token quietly expires; the resource API's activation fails outright, and the 401 it sends back cannot carry the ball — a failed activation hands nothing to a successor — so the app backend's refresh starts from a token run.inject() mints on its own lifeline at the instant the failure lands.

    What to look for

    • PKCE: the code_verifier never leaves the app backend. Only the code and its challenge cross through the browser, so a stolen authorization code is useless to anyone who doesn't hold the verifier that minted its challenge.
    • Every redirect between the app and the identity provider bounces through the browser — the two never talk to each other directly during login, only during the code exchange and the later token refresh.
    • 55 minutes on, the access token has expired: the resource API's activation fails outright (red) and stops there. A failed activation is terminal for its branch — no finish event, no token out along the 401 arrow — so the page listens for that fail and calls run.inject("app.5"), minting the refresh token on the app backend's lifeline at the failure's own instant.
    • The Resource API lifeline goes red on the 401 and clears again when the retried call succeeds: each actor declares statusAgg: "latest", so one failed call does not paint the column red for the rest of the story.
    • The identity provider rotates the refresh token on every use, so the old one is dead the moment the new pair is issued.
    • Each message carries its own wire time (edge.data.duration): the back-channel POST /token round trip to the identity provider visibly outlasts a same-region GET /me. Click any activation to pick its row out of the message list (g.on("nodeclick")).
