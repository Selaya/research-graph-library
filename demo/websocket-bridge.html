Live WebSocket bridge — Mode B, fed by a socket that drops mid-run

Nothing here is simulated from declared durations. A tiny in-page MockSocket — the same surface a browser WebSocket gives you (onopen, onmessage, onclose, send, close) — streams JSON frames from a fictional CI server, and each frame is forwarded straight into g.run({mode:"live"}) as run.start/finish/fail/spawn, exactly like the wiring example in docs/LIVE.md. Halfway through the deploy the socket is reset; the build keeps going without us; the client reconnects, asks for everything it missed, re-seeds the run with run.reset({log}) and fast-forwards back to live.

What to look for

  • Real events, not a schedule. Every status change on screen is one JSON frame in the panel on the left. The duration chips are the declared estimate (data.duration); the live feed is what actually happened, compressed.
  • The socket dies during DB migrate. The graph freezes on its last known state (warn highlight, everything else dimmed) while the server keeps building.
  • Resume, then catch up. The client sends {"type":"resume","since":…}, the server replays the frames it missed, run.reset({log}) re-seeds the same run object, and speed(8) + play() fast-forwards the view back to the frontier.
  • A failure the log carries. Smoke test fails with reason: "readiness probe: 503 …" — the branch simply stops; nothing fans out to Promote to prod.
  • The retry ticks the loop edge. Restarting Deploy canary over the dashed loop:true, maxIterations:3 back edge is the live iteration — watch the badge go 1/3.
  • Runtime fan-out. spawn("warm", 3) puts four tokens on Warm CDN cache (one per PoP) — the ×4 occupancy badge.
  • Two clocks. Scrub backward and the view detaches from the frontier; live time keeps flowing underneath and you can never scrub past it. Follow live snaps back.
