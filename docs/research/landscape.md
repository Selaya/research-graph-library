# Research: Landscape survey — build vs. adopt

> One of 7 parallel research passes behind docs/PLAN.md · 2026-08-29

## Summary

No existing library satisfies the requirements well enough to skip building. Cytoscape.js is the closest generalized fit (rich compound-node model, huge extension ecosystem, MIT) but its core alone plus the expand-collapse and dagre extensions needed for our exact requirements pushes well past a ~50KB gzip budget, and none of its animation is built for narrative "N nodes morph into 1" or scrubbable-playhead semantics — those would be hand-built by us regardless of base library. Everything else fails on a different axis: vis-network/mermaid/G6/X6/JointJS/GoJS are too heavy or commercial or React-coupled; drawflow/reaflow are too shallow (no layout/hierarchy engine) or not build-free. Verdict: build a small purpose-built rendering+animation+diff engine, optionally reuse `@dagrejs/dagre` (not `dagre`, not `elkjs`) as a pluggable layout adapter, and borrow specific mechanics (compound collapse-to-meta-edge, declarative enter/update/exit animation, data/display graph separation) rather than any whole library.

## Recommendation

(1) BUILD, don't adopt. Nothing combines "single script tag / no build, well under 50KB gzip" with "first-class animation for append+playhead+morph" and "animated per-node compound expand/collapse" — these three constraints alone eliminate every existing library. Cytoscape.js is the best-engineered generalized graph model to study but not to embed wholesale (see sizes below); use it as a design reference, not a dependency.

(2) LAYOUT: ship a small hand-written longest-path/Sugiyama-lite layered layout as the zero-dependency default (pipeline DAGs in the motivating use case are shallow — tens of nodes, not thousands — so a simplified ranking+ordering pass is tractable and keeps the core dependency-free and synchronous, which matters for frame-by-frame animation control). Offer `@dagrejs/dagre` (the actively-maintained scoped fork; the original unscoped `dagre` is deprecated — do not depend on it) as an optional pluggable adapter for users who want its network-simplex ranker on more complex graphs. Do NOT default to or bundle `elkjs`: it is confirmed ~1.45MB unpacked (GitHub issue reaviz/reaflow#224), runs async/worker-based (fights per-frame animation timing), and would alone consume 5-10x the entire size budget. `d3-dag` is a credible middle option (MIT, actively maintained, synchronous, more modern crossing minimization than dagre) worth a second optional adapter, but dagre's ecosystem precedent (used by mermaid, X6, React Flow, cytoscape.js-dagre) makes it the safer default plugin.

(3) BORROW (5): (a) Cytoscape.js's unified declarative elements-spec + separate stylesheet + full imperative mutation API on one live object (`cy.add/remove/animate`), plus its `cytoscape.use()` extension-registration pattern for keeping core lean. (b) cytoscape.js-expand-collapse's mechanic of turning a collapsed compound node into a real proxy node with synthesized "meta-edges" that aggregate child edges — this is directly the mechanism needed for "several manual steps condense into one automated node" and for collapse/expand without edges vanishing. (c) AntV G6 v5's per-element declarative animation config (enter/update/exit/collapse-expand timing+easing declared as data, not imperative code) — keeps animation first-class in the spec as required. (d) D3's general update pattern (enter/update/exit joins) and d3-interpolate/d3-transition's tweening primitives — the conceptual foundation for "append at end" and smooth attribute transitions; reimplement a tiny tween engine rather than pulling the dependency. (e) sigma.js's "reducers" pattern — pure functions computing per-frame display attributes without mutating the underlying data graph — cleanly separates the declarative graph-spec (data) from animation/render state (display), which is exactly the separation needed to let a playhead or morph animation run without corrupting the source-of-truth spec. Also borrow GoJS/yFiles' idea of an internal reconciler that diffs old vs. new declarative state and auto-generates enter/update/exit/move animations, rather than requiring hand-written transitions per mutation — this is the single highest-leverage idea for meeting "smooth animated transitions whenever the graph changes" generically.

MISTAKES TO AVOID (5): (a) vis-network's mandatory always-on physics/Barnes-Hut simulation baked into a non-tree-shakeable monolith (~500KB+ min) — don't force a force-directed simulator into the core when the motivating case is a static layered DAG. (b) elkjs/GWT-cross-compiled-from-Java layout code — porting a heavyweight non-native algorithm wholesale produces huge, worker-only, hard-to-tree-shake output; write native small JS instead. (c) Mermaid's kitchen-sink bundle (2-2.8MB min) supporting a dozen unrelated diagram grammars in one artifact — keep the core graph/animation engine narrow; let pipeline-specific chrome (duration bars, step numbers) be a thin theme layer, not baked into core. (d) JointJS/GoJS gating the actually-hard differentiating features (advanced compound collapse/expand, advanced layout, React bindings) behind a second paid tier (JointJS+ from $sub, GoJS perpetual license from $3,995/developer) — build our expand-collapse and morph animation into the free OSS core from day one, since that gap is the whole point of this project. (e) The cytoscape ecosystem's extension-fragmentation — expand-collapse, dagre-layout, and other essentials are separate third-party packages with independently lagging maintenance (e.g. cytoscape.js-expand-collapse: 140 stars, 32 open issues, iVis-at-Bilkent) and version-compatibility matrices; bake expand/collapse, layered layout, and morph animation into our core so they can't drift out of sync — reserve the plugin system for genuinely optional things (alternate layouts, alternate renderers).

## Why "build" wins decisively
Three requirements together form a filter nothing passes: (1) under ~50KB gzip, single script tag, zero build step; (2) first-class, generalized animation for append/playhead/morph; (3) animated per-node compound expand/collapse baked in, not bolted on. Every library that clears (1) — drawflow, raw d3-force, a bare cytoscape core — fails (2) and (3) outright (no hierarchy engine, no morph semantics). Every library that clears (2)/(3) reasonably well — G6, X6, GoJS, JointJS+, reaflow — fails (1) by being either heavy, commercial, or framework-coupled. Cytoscape.js sits closest to the intersection but still requires stacking 2-3 independently-maintained extensions to reach parity, and even then its animation model is generic tweening (position/style easing), not a semantic "these 4 nodes condense into 1, and the visual language should communicate a speed-up" primitive — that primitive does not exist in any surveyed library and must be authored regardless of what we build on.

## Layout recommendation detail
Given the primary use case (a pipeline: tens of steps, occasionally expanding to tens of substeps — not thousands of nodes), a from-scratch simple layered layout (rank assignment by longest-path or topological order, naive left-to-right ordering, incremental re-rank on morph/collapse) is both feasible and preferable as the zero-dependency default, because: it stays synchronous (critical for computing intermediate frames during a layout-change animation — async/worker-based elkjs make it much harder to interpolate positions frame-by-frame), it stays tiny, and it avoids taking on an external maintenance dependency for the single most core piece of the product. Offer `@dagrejs/dagre` as an optional, tree-shaken-out-by-default adapter (`import {dagreLayout} from 'ourlib/layouts/dagre'`) for users hitting the edges of the naive layout on larger/denser DAGs, and consider `d3-dag` as a second adapter option for its superior crossing minimization. Never bundle `elkjs` by default; expose it only as a documented "bring your own heavy layout" escape hatch loaded from a separate CDN URL.

## Notable gaps confirmed across the entire landscape
No surveyed library has a named "node condensation/morphing" animation primitive (several nodes visually merging into one with a rate/speed cue). The closest analogues are: cytoscape.js-expand-collapse's collapse-to-proxy-node-with-meta-edges (structural, not narrative), GoJS/yFiles' generic animation managers (imperative, not declarative-morph), and D3's enter/update/exit pattern (general-purpose, requires bespoke authorship for the merge case). This confirms the graph-morphing requirement is genuinely novel work for this project, not something to source from an existing library.

## Risks & caveats

- **Unverified exact bundle-size figures**: bundlephobia.com, jsdelivr.com, unpkg.com, pkg-size.dev, and packagephobia.com were all blocked by the sandbox's egress proxy this session, so most min+gzip numbers above are "commonly cited" community figures rather than freshly measured ones. The directional conclusions (cytoscape/vis-network/G6/X6/JointJS/GoJS/mermaid all meaningfully exceed a ~50KB budget; elkjs is enormous; dagre-family layouts are small) are corroborated by multiple independent sources and a hard confirmed number for elkjs (1,451KB unpacked, from a live GitHub issue), so confidence in the "build, don't adopt" conclusion is high — but exact numbers should be re-verified with a live bundlephobia/pkg-size check before writing them into any public comparison table or marketing copy.
- **sigma.js v4 alpha**: sigma is mid-major-version-transition (v3 stable, v4 alpha in progress) — its animation/reducer API may change meaningfully; if this project wants to borrow sigma's "reducer" pattern, revisit against v4 once stable rather than v3's exact API.
- **vis-network health**: 347 open issues on a 3.6k-star repo, plus its predecessor `visjs/vis` being explicitly marked "not maintained," suggests vis-network itself may be trending toward reduced maintenance — worth periodically re-checking if any design decision ends up depending on it (current recommendation does not).
- **drawflow momentum**: last version published roughly 2 years before this research date despite 272 open issues — treat it as a UX/embedding-simplicity reference only, not as evidence that "small vanilla JS graph libraries" are a thriving, well-supported category to lean on.
- **License nuance on JointJS/GoJS**: JointJS core (MPL-2.0) is legitimately reusable/embeddable OSS, and its architecture (cells, embedding, plugin ports) is worth studying even though its *advanced* features are commercial — don't conflate "JointJS the free core" with "JointJS+ the paid product" when citing it as a design reference.
- **d3-dag license/algorithm fit unverified in depth**: confirmed actively maintained and MIT-licensed with a strong star-to-issue ratio, but this research did not deeply verify its performance characteristics on the specific "expand a high-level node into a live subgraph" incremental-relayout pattern our use case needs — worth a focused spike if it's chosen as the secondary layout adapter over dagre.
- **Newer/smaller libraries may exist below the search horizon**: cosmos.gl/Cosmograph is the newest notable entrant found and is a poor fit (optimized for flat force-directed point-cloud scale, not hierarchical narrative animation); it's possible an even newer 2026 micro-library exists that WebSearch didn't surface — recommend one more narrow search pass ("javascript pipeline visualization library expand collapse animation 2026") closer to build time as a final check before committing to "build from scratch."
