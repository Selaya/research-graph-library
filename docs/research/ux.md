# Research: Pipeline UX & motion design

> One of 7 parallel research passes behind docs/PLAN.md · 2026-08-29

## Summary

Researched CI/CD and workflow-viz prior art (GitHub Actions, GitLab pipeline graphs, Dagster asset graph, Airflow Grid/Graph, Temporal Timeline), node-editor expand/collapse conventions (Cytoscape.js expand-collapse, React Flow sub-flows), and motion-design literature (Heer & Robertson 2007, Material "container transform," Framer Motion FLIP/layoutId, D3 object constancy/general update pattern, Flubber shape interpolation). Converged on a storyboard: state-styled rounded-rect nodes with duration chips and manual/automated iconography; a dual playhead model (traveling edge/node pulse for DAG view, sweeping vertical line for Gantt/temporal view); FLIP-based container-transform expand/collapse with a mental-map-preserving relayout; a staged 3-phase condense/morph animation (highlight→converge→reveal delta) that pairs topology merging with an explicit duration-shrink/odometer readout, since no prior-art tool actually shows "N manual steps become 1 automated step, X hours become Y seconds" as one animation — this is the one truly novel, pipeline-specific choreography to design deliberately. Everything else (status styling, timeline/playhead, group expand-collapse, N→1 morph, zoom/fit, small-multiples diff) is proposed as a general core primitive, with duration bars, manual/auto badges, and the time-saved delta treated as a pipeline preset/theme layered on top.

## Recommendation


**Core primitives to ship in the library core (domain-agnostic):**
1. **State-styling system**: nodes/edges get style resolved from declarative `status`/`kind` fields via a token map (color, icon slot, border style) — not hardcoded to CI/CD vocabulary, but ship a default status palette (pending/active/done/error/skipped) as the built-in theme.
2. **Progress-cursor ("playhead") primitive**: an abstract cursor that advances over an ordered sequence of node/edge IDs, driving (a) sequential highlight-pulse animation along traversed edges and (b) a settling state-change on arrival at each node. This is generic enough for tutorials, state machines, or story graphs, not just pipelines.
3. **Compound-node expand/collapse**: FLIP-based container-transform — measure collapsed bounding box, swap in child subgraph, animate width/height/position of the container and fade+scale children in from the container's last known rect; re-layout via an incremental/deterministic algorithm (not randomized) to preserve the mental map, following Cytoscape.js's `cose-bilkent randomize:false` convention and Dagster's group-collapse UX. Ship both an "in-place" (siblings reflow) and "overlay/focus" (rest of graph dims, subgraph zooms to fill) mode as two presets of the same primitive.
4. **N→1 / 1→N morph primitive**: generic merge/split animation keyed by object-constancy IDs (à la D3 `selection.join`/general update pattern): old elements each get a mapping to a target node; animate position/scale convergence (or divergence) with a crossfade at the moment of merge. Bounding-box morphing (x/y/width/height/rx tween) should be the default — avoid pulling in full path-interpolation (Flubber-class) libraries for standard rect/circle nodes to keep bundle size down; expose an optional shape-morph hook for custom node renderers that need it.
5. **Zoom/pan/fit-to-view**: `fitView()`-style API (React Flow/Cytoscape convention) with animated re-fit (300–500ms ease) triggered automatically after topology-changing operations (expand/collapse/merge/append), plus focus-to-subgraph. Minimap as an optional overlay component, not core.
6. **Small-multiples / diff view**: render two graph snapshots (by ID-keyed diffing) side-by-side or stacked with linked pan/zoom and a shared scale, as the "study" complement to the "reveal" animation — grounded in Heer & Robertson's finding that animation aids attention/tracking but static comparison aids precise analysis, so ship both rather than picking one.

**Pipeline-specific sugar → ship as `preset-pipeline` (theme/plugin, not core):**
- Duration-aware node width and inline mini-duration-bar (Gantt-in-miniature inside the node).
- Manual-vs-automated iconography (hand/person badge vs. gear/lightning badge) and duration formatting (`~2h` vs `8s`).
- Gantt/temporal layout mode where x-position encodes time, enabling a literal sweeping-vertical-line playhead (video-editor scrubber convention) as an alternative to the topological pulse playhead.
- The "time-saved" condense choreography: on top of primitive #4, add (a) a duration chip that number-tweens/odometers from the old summed value to the new value, (b) the inline mini-bar shrinking in width proportionally, (c) a transient delta badge (`2h → 8s · −99.9%`). Stage this in 3 phases per Heer & Robertson's staging principle for complex transitions: **highlight** (the N source nodes get a shared outline/glow, ~150ms) → **converge** (nodes animate position/scale toward the target centroid while crossfading, ~400–600ms, eased) → **reveal** (new merged node settles, duration chip odometers down, delta badge pops in, ~300ms). Total ~900ms–1.2s; provide a "step through" mode (click-to-advance phases) for presentations, and an instant/crossfade fallback for `prefers-reduced-motion`.
- CI/CD-flavored status vocabulary and icon set (pending/running/success/failed/skipped/manual/blocked) as the default theme values plugged into primitive #1.

**Node visual language (pipeline preset):** rounded-rect card, left accent bar or ring in status color, status glyph top-left (clock=pending, spinner/pulsing dot=active, check=done, x=error, dashed=skipped), duration chip top-right, manual/auto badge bottom-left, compound-node affordance = stacked-card shadow + chevron/expand icon bottom-right (distinguish "has children" from "is a leaf step" at a glance, borrowing GitLab's expandable mini-pipeline-graph stage convention and Dagster's group nodes).

**Playhead motion spec:** default = traveling pulse: a bright dot/gradient travels along the edge path (SVG `stroke-dashoffset` or a small element following `getPointAtLength`) at ~600–900ms per edge hop, arriving node triggers a brief scale/glow "active" pulse (200ms) then settles to "done" style; edges already traversed get a persistent subtle fill/glow so progress-so-far reads as a filled path (progress-fill edges), similar in spirit to Temporal's colored timeline spans and GitHub Actions' completed-vs-pending job coloring.


## Details


**Prior art surveyed and what to borrow:**

| System | Relevant pattern | Applicability |
|---|---|---|
| GitHub Actions workflow graph | Per-job status icon + dependency lines drawn from `needs:`; known UX complaint that the graph box dominates layout and blocks page-scroll when hovered (community discussion #18035) | Borrow: icon+line vocabulary. Avoid: don't let the graph canvas capture scroll/zoom without an explicit "focus" affordance (e.g. click-to-activate pan/zoom, or ctrl+scroll to zoom) |
| GitLab pipeline graph & "mini pipeline graph" | Full graph vs. compact mini-graph of the same data; mini-graph stages are click-to-expand; jobs sorted by status severity (failed first) then alphabetically; "Show dependencies" toggle overlays `needs` lines only on demand | Borrow: dual full/mini rendering of one spec (maps to our "collapsed" node state); toggleable dependency-edge overlay as a generalizable feature (edges as an optional layer, not always-on) |
| Dagster asset graph | Collapsible/expandable groups with dedicated "expand/collapse all" control; explicit complaint that random relayout after expand disorients users at scale; sidebar navigation as an alternative to pure pan/zoom for very large graphs | Confirms: relayout-preserves-mental-map is a real, repeatedly-requested need, not a nice-to-have. Borrow: expand/collapse-all control, sidebar/outline nav as a preset for large graphs |
| Apache Airflow Grid + Graph views | Two coordinated views of one DAG: Graph = topology + per-run status; Grid = duration/outcome history across many runs as a compact heatmap-like grid; switching between DAG runs updates Graph view state | Confirms value of pairing a topological view with a *temporal/historical* view — supports shipping both a DAG-layout mode and a Gantt/temporal-layout mode off the same spec |
| Temporal Web UI Timeline view | Horizontal spans colored by outcome (green=completed, red=failed) grouped into rows by "Event Group" (collapses 3 related low-level events into 1 visual row); hover tooltip shows exact start/end/duration to the millisecond | Directly informs the Gantt/temporal playhead mode: span width = duration, color = outcome, grouping = our compound-node collapse |
| Cytoscape.js `expand-collapse` extension | `animate`/`animationDuration` (default 1000ms) options; `fisheye` post-expand option; `layoutBy` re-layout hook; explicit doc guidance to pair with `cose-bilkent` + `randomize:false` "to preserve mental map upon expand/collapse"; collapses parallel edges between the same node pair into a single meta-edge with direction metadata | Directly reusable API shape for our compound-node primitive; the meta-edge-collapsing behavior is exactly the edge-rerouting needed for our expand/collapse and also foreshadows the N→1 merge primitive |
| React Flow sub-flows / expand-collapse example | `parentId` + `extent:'parent'` for compound nodes; expand/collapse via a hook that keeps full graph in memory and toggles visibility (`hidden`) rather than mutating data; group nodes render without handles | Confirms the "full graph kept in memory, visibility toggled" implementation pattern — keeps mutation API simple (one JSON graph, view state layered on top) |
| Heer & Robertson, "Animated Transitions in Statistical Data Graphics" (IEEE TVCG 2007) | Taxonomy of transition types; design principles: use object constancy (stable keys), stage complex multi-part transitions into distinct phases rather than animating everything at once, and animation significantly improves graphical perception/trackability in controlled experiments vs. no animation | Directly grounds: (1) our staged 3-phase condense choreography, (2) the requirement for ID-keyed object constancy across all our transitions (this is *the* academic grounding for "why animate graph state changes at all") |
| Material Design motion ("container transform," "shared axis," "fade through") | Container transform: one element visibly morphs into another via shared bounding-box + color match, used for list-item→detail-page expansion; principle: transitions must be simple/coherent, avoid doing too much at once, give a clear focal point | Directly maps to our expand/collapse (container transform: leaf node → subgraph container) and is a second, independent citation validating the staging principle |
| Framer Motion `layoutId` / FLIP | Removing an element and mounting another with the same `layoutId` at the same time makes Motion morph one into the other automatically via FLIP (First-Last-Invert-Play), computing before/after bounding boxes | Validates implementation approach for expand/collapse and merge without needing a heavy animation engine — bounding-box FLIP is sufficient for rect/circle nodes |
| Flubber (SVG path morphing) | Interpolates between arbitrary SVG paths/point-rings, handles differing vertex counts; used for shape-to-shape morphs beyond simple boxes | Useful only if we support arbitrary custom node shapes; NOT needed for default rect/pill nodes — flag as an optional add-on to protect bundle size, not a core dependency |
| D3 object constancy / general update pattern / `selection.join` | Object constancy requires a stable key function; merge of enter+update selections lets one code path drive both "arrived" and "already there" animation; exit selections get their own transition-out | This is the correct general mechanism underlying primitive #4 (N→1 merge) — old node's key resolves to new node's key, drives the FLIP/converge animation, and nodes with no successor get the exit-transition (fade+shrink) |
| n8n / Node-RED execution visualization | n8n shows an "execution animation" badge/pulse on nodes as data flows through; behavior is sometimes buggy when idle (community bug report) — cautionary tale for keeping animation strictly state-driven, not decorative/looping by default | Cautionary: playhead/pulse animation must be strictly bound to actual state changes (avoid idle-looping animation that misleads about live status) |
| Timeline scrubber / playhead UX (video editors) | "Playhead" = vertical line marking current position; scrubbing = dragging it; snapping to clip boundaries / frame boundaries; haptic/visual snap feedback | Directly informs the temporal-layout playhead: a draggable vertical line the user can scrub across pipeline steps, snapping to step boundaries, to manually scrub through run history (not just auto-play) |

**Condense/morph animation — detailed storyboard (the one genuinely novel piece):**
Starting state: N manual step-nodes in a row, each with a clock-icon duration chip (e.g., `45m`, `1h`, `20m`, `15m` = 2h total), connected in sequence.
1. *Trigger* (data change: those N nodes' `automatedBy` or `mergedInto` field now points to one new node ID).
2. **Highlight phase (~150ms)**: the N source nodes get a shared colored outline/glow and a connecting dashed "grouping" line appears beneath them (like a bracket), signaling "these are about to become one thing" — gives the eye a moment to register *which* nodes are affected before anything moves (staging principle, Heer & Robertson).
3. **Converge phase (~400–600ms, eased, e.g. cubic-out)**: the N node shapes animate (via bounding-box FLIP tween) toward a shared centroid, shrinking in scale as they approach, while their edges retarget/reroute in parallel (edge endpoints tween toward the converging point) so nothing visually detaches. At ~70% progress the N shapes crossfade into the single new automated-node shape (gear/lightning badge) rather than literally becoming N overlapping rectangles at the end — avoids a messy multi-overlap frame.
4. **Reveal phase (~300ms)**: the merged node settles into final size/position; its duration chip odometer-tweens numerically from the old summed value to the new value (`2h → 8s`, digits rolling like an odometer or a quick counting animation); a small transient delta badge (`−99.9%` or `14x faster`) pops in beside it and fades after ~1.5s (or stays pinned if the user hovers); the mini-duration-bar inside the node visibly shrinks from a wide bar to a sliver in the same beat as the odometer.
5. Provide `prefers-reduced-motion` fallback: skip straight to crossfade (150ms) with the delta badge appearing immediately, no spatial convergence.
6. Provide a reverse/expand version (1→N) using the same primitive for "de-automate"/drill-into-history use cases.
7. Provide a companion **static comparison mode**: a small-multiples panel showing the "before" mini-graph (N nodes, total 2h) and "after" mini-graph (1 node, 8s) side by side with a shared duration axis/bar-chart underneath (a literal bar shrinking, not animated) — this is the artifact a user screenshots or embeds in a report, separate from the live animation.

**Zoom/pan/fit specifics:** default `fitView`-equivalent on initial render and after any topology-changing op, animated 300–500ms ease-out with 10–15% padding; ctrl/cmd+scroll or a two-finger gesture to zoom (avoid hijacking plain scroll per the GitHub Actions complaint above); double-click a compound node = zoom-to-fit that node's expanded subgraph ("focus" mode); minimap and outline/sidebar nav (Dagster-style) as optional preset components for large graphs, not core.

**API surface implication for other dimensions:** the animation model needs (a) a stable ID/key on every node and edge (object constancy is non-negotiable — without it none of D3-general-update-pattern-style merge/expand animation is coherent), (b) a way to express "this set of old IDs maps to this new ID" in the mutation API (e.g., `graph.condense({from: [...], to: {...}})`) as a first-class op distinct from generic add/remove, because the merge semantics can't be reliably inferred from a diff alone, and (c) a declarative `status`/`kind` field per node that the core state-styling system consumes.


## Risks & caveats


- **Staged multi-phase animations (highlight→converge→reveal) are the hardest thing to keep both smooth and small in bundle size.** Naive path-morphing (Flubber-class) libraries add real KB; the recommended mitigation (bounding-box/FLIP tweening for default rect/circle nodes, path-morph only as an opt-in for custom shapes) needs validation against the size budget from the bundle-size research track — flag for cross-check with that dimension.
- **No direct prior-art precedent for the "N manual steps → 1 automated step + time-saved readout" animation** — GitHub Actions, GitLab, Dagster, Airflow, Temporal all show topology and status, none show a duration-delta merge animation. This is genuinely novel design surface, meaning there's no reference implementation to crib exact timings/easings from; the ~900ms–1.2s / 3-phase timing above is a synthesis from Heer & Robertson's staging principle and Material's container-transform guidance, not a measured/tested number — should be user-tested once built.
- **Mental-map preservation during expand/collapse and merge is the single most-cited failure mode** in prior art (Dagster users explicitly complain about randomized relayout; Cytoscape docs stress `randomize:false`). If the library's default layout algorithm re-randomizes node positions on any state change, all the animation polish will read as jarring rather than smooth — this constrains the layout-engine choice (a concern for whichever dimension picks the layout algorithm) to one that supports incremental/stable positioning.
- **Auto-playing or idle-looping animation risks misleading users about live status** (the n8n community bug report of animation showing when nothing is running is a cautionary real-world example) — the design must strictly gate all motion on actual state transitions, never decorative loops, and must respect `prefers-reduced-motion`.
- **Two coexisting layout modes (topological DAG vs. Gantt/temporal-with-playhead-scrubber)** roughly double the surface area of "expand/collapse/merge must animate correctly here too" — recommend the pipeline preset ship the Gantt/temporal mode as clearly optional/secondary to keep initial scope and testing surface bounded, deferring full scrubbing/snap interactions (borrowed from video editors) to a later iteration.
- Sources reflect current-as-of-2026 web search results; several official design-spec pages (design.gitlab.com, docs.gitlab.com) were blocked by network egress policy in this environment and were not directly fetchable — GitLab claims above rely on search-snippet summaries rather than a full page read, so treat GitLab-specific details as lower-confidence than the GitHub/Dagster/Cytoscape/Temporal/academic citations, which were corroborated by fuller fetch or multiple consistent search snippets.
