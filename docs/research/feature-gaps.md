# Research: Feature gaps vs. other node/edge libraries, and additional use-cases

> Research sweep of 2026-09-05 · 13 cohort surveys, each verified against the repo · 8 use-case perspectives · one completeness critic · synthesized report
>
> Follow-up to `docs/research/landscape.md` (a build-vs-adopt survey written before the library existed); this pass compares the SHIPPED library (v0.1.0) against what other node/edge tools actually offer today.

## Summary

Twelve cohorts of node/edge, diagramming, orchestration, observability and presentation tools were surveyed and every claimed gap was checked against this repo, which produced 261 verified claims (212 missing, 45 partial, 4 already present) collapsing to about 130 distinct gaps after merging duplicates across cohorts. The library's distinctive assets held up under comparison: the Mode B append-only event log with a frontier/view two-clock time-travel model, the compiled Mode A token schedule with join policies and bounded retry loops, animated compound expand/collapse with meta-edge aggregation, condense/split choreography, and the storyboard plus cue-sheet plus deterministic recorder toolchain are collectively unmatched in the surveyed set. The largest structural gap is not a layout algorithm: it is that nothing can get data in and nothing can get a narration onto real data. There is no importer of any kind (no DOT, GraphML, OTLP, workflow YAML, dbt manifest, event-log CSV), so every one of the 73 use-cases collected below begins with a hand-written adapter. Storyboards, captions, camera ops, `smv-record` and `smv-fit` are all Mode A only by deliberate design, which walls the entire narration and recording toolchain off from exactly the runs (real logs) that postmortems, incident reviews, live dashboards and trace explainers want to narrate. Below that sit three gaps named independently by six or more perspectives: no pointer events on nodes or edges (so no tooltip, no click-to-drill, no search UI, no selection), no live numeric text channel on nodes or edges (so throughput, counts, elapsed time and cost cannot be shown), and no time axis (the Gantt/temporal layout mode was explicitly skipped, yet duration and overlap are the primary question in CI, tracing, capacity and roadmap work). Interactive-editing gaps (node dragging, marquee select, undo/redo, clipboard, stencil palettes, edge drawing) are numerous but almost all fall outside the stated remit and should be declined rather than scheduled. Alternative layout families (force, radial, circular, tree, Sankey) are real gaps but low fit, and the existing `LayoutSolver` seam already accommodates them as optional adapters if demand appears. The highest-value work is small and additive: pointer events, a tooltip preset, a live label channel, a pure-function analysis subpath, one or two importers, and a route from a finished event log into the Mode A narration toolchain.

## Method

Twelve cohorts were surveyed: (1) cytoscape.js plus its extension ecosystem, sigma.js and graphology; (2) vis-network, Apache ECharts and Plotly.js; (3) AntV G6 and X6; (4) commercial diagramming (JointJS/JointJS+, GoJS, yFiles for HTML, Syncfusion Diagram); (5) the React Flow family (xyflow React/Svelte, Vue Flow, reaflow); (6) text-to-diagram tools (mermaid, D2, Graphviz/viz.js/d3-graphviz, PlantUML); (7) d3 micro-libraries plus dagre-d3, elkjs and WebCola; (8) node editors (Rete.js, litegraph, Drawflow, Baklava, Node-RED, n8n, ComfyUI, Blender, Unreal Blueprints); (9) pipeline/orchestrator UIs (Airflow, Dagster, Prefect, Argo, Temporal, Kubeflow, GitHub Actions, GitLab, Blue Ocean, Tekton, Azure DevOps, Buildkite); (10) observability and state tools (Jaeger, Grafana Tempo and Node Graph, Kiali, Datadog and New Relic service maps, Perfetto, XState/Stately inspect, bpmn-js, Camunda); (11) animation and presentation tooling (Motion Canvas, Manim, Remotion, GSAP/Flip, anime.js, Excalidraw, tldraw, reveal.js/Slidev, Figma Smart Animate, Loom, Screen Studio); (12) large-scale and analytics tools (Cosmograph/cosmos.gl, Ogma, KeyLines/ReGraph, Gephi Lite, ngraph, G6, graphology algorithms). A thirteenth catch-up sweep added prior art the first twelve missed (Rough.js/RoughViz, vis-timeline, Frappe Gantt, Konva, Fabric, Lottie, Perfetto, Speedscope, draw.io embed, Structurizr, `@statelyai/inspect` replay).

Every claimed gap was then verified against this repository by reading `src/`, `types/index.d.ts`, `README.md` and `docs/`, and labelled present, partial or missing with a file-and-line citation. Claims that turned out to be present were dropped from the catalogue. In parallel, eight perspectives generated use-cases independently and judged each against the same code: developer tooling and CI/CD, data and ML platform, LLM agent systems, business process and operations, education and technical writing, SRE and observability, product management and solutions engineering, and systems/simulation modeling. A completeness critic then reviewed the whole sweep for missed prior art, missed feature areas and dubious gaps; its findings are folded in (the catch-up cohort, the voice-over tooling gap, and the de-duplication of the force-directed and framework-wrapper claims).

Limitations, stated honestly. Web access was partially blocked by the sandbox proxy: `js.cytoscape.org`, `graphology.github.io`, `visjs.github.io`, the AntV docs, `reactflow.dev` and `svelteflow.dev` could not be fetched, so several capability descriptions rest on search-result snippets or on model knowledge and are marked "from memory" in the surveys. Claims sourced that way are still verified on the repo side (the "today" column of every table below reflects an actual code read), so a from-memory claim can at worst overstate what a competitor ships, never what this library ships. Version numbers appear only where a registry or docs page confirmed them; everything else is recorded as "unknown" rather than guessed, and no version was invented. Commercial products (GoJS, yFiles, Syncfusion, Ogma, KeyLines) publish no reliable public version string and are listed as unknown. Fit scores are 1 (out of remit) to 5 (core to the library's stated purpose) and reflect this project's own goals, not general desirability.

## Borrowable ideas

API shapes and UX patterns worth copying, deduplicated across cohorts.

- Reducer-style display functions: pure `(id, attrs) => displayAttrs` computed per frame from the model rather than baked into it (sigma.js). Close to `g.style(fn)` already; the naming would sharpen the docs.
- Plugin/preset registry declared as data, e.g. `plugins: [{type: 'minimap', ...opts}]` (AntV G6), and a flat named-behavior array like `['drag-canvas','zoom-canvas','click-select']` (G6 behaviors) instead of growing boolean mount options.
- Granular render-pipeline override seams: `render().createNodes` / `createEdgePaths` (dagre-d3) let a preset replace one drawing stage rather than the whole renderer.
- A `Router`/`Connector` split registered by string name (X6), and the `EdgeRouter` family naming (yFiles: OrganicEdgeRouter, ParallelEdgeRouter, SelfLoopRouter): edge routing as a seam distinct from node placement.
- Independently swappable layout stages: `.layering()`, `.decross()`, `.coord()` (d3-dag).
- Declarative constraint objects as plain JSON, e.g. `{type:'alignment', axis, offsets}` (WebCola), which would compose with the storyboard op vocabulary as a `constrain` op without importing a physics solver.
- Per-node inline layout overrides carried in the graph data itself (elkjs `layoutOptions` on a node or port).
- `addCustomTime(time, id)` for multiple named, movable, independently addressable markers on one timeline (vis-timeline), directly portable to voice-over sync points.
- Event grouping: collapse raw scheduled/started/completed events into one span with a duration (Temporal event groups). Cheap to add as `run.spans()` and unlocks tooltips, exports and a future Gantt view.
- Two views of the same data behind one toggle: stage order versus dependency order (GitLab "group jobs by"), a clean model for declared grouping versus computed rank.
- A separate viewport linked to the main one, with a draggable rect (GoJS `Overview`, cytoscape-navigator), and Speedscope's click-to-zoom-into-a-frame with a breadcrumb stack to zoom back out.
- `<Panel position="top-left">` as a declarative slot for arbitrary viewport-anchored UI (React Flow), which the caption overlay could generalize into.
- `popperRef()`: a stable, animation-synced screen-position accessor per element that any HTML overlay library can anchor to (cytoscape-popper). `viewport.worldToScreen` is most of this already.
- `isValidConnection(connection)` as a host-supplied pure predicate (xyflow), useful as a validation hook on programmatic `addEdge` even without interactive drawing.
- Action registration with automatic batching: `ur.action(name, doFn, undoFn)` plus `do('batch', [...])` (cytoscape-undo-redo), and the event-sourced typed history of Node-RED's `RED.history`.
- `cy.json()` / `toObject()` / `getOption()` as a single full-fidelity snapshot including viewport and style, restorable by handing it back to the constructor.
- `saveJson()` / `loadJson()` for just the collapsed-state map, separate from the graph spec (cytoscape-expand-collapse).
- Verb pairs that read well: `cluster()`/`openCluster()` (vis-network), `condense()`/`split()` (this library) and X6 History's `undo()/redo()/canUndo()/canRedo()`.
- `stagger()` with `from: 'first' | 'last' | 'center' | 'random' | index` as a timing-offset utility pluggable anywhere a delay is accepted (anime.js).
- `Flip.getState()` / `Flip.from()`: FLIP exposed as a public capture-and-animate primitive, not only an internal mechanism (GSAP), so a consumer can animate their own DOM on the library's ticker.
- Per-tween verbs `play/pause/reverse/seek/reset/finish` (Konva.Tween). The missing verb here is `finish()`/`skipToEnd()` on mutation handles, which today only offer `cancel()`.
- Generator-based flow control with `waitFor`, `waitUntil`, `all`, `chain`, `sequence` and a timeline UI showing named events as draggable markers (Motion Canvas).
- A versioned declarative animation document with per-layer keyframe tracks, a `v` schema field and a named `markers` array, played by a portable runtime (Lottie/Bodymovin). The storyboard array should carry a schema version for the same reason.
- Parametrized single-frame rendering (`renderStill` with `inputProps`) alongside full video rendering (Remotion).
- Activity-keyed automatic camera: derive zoom and pan from where the action is, rather than hand-keying every move (Screen Studio).
- A telestrator laser pointer whose concurrent strokes fade as a group, exposed as a general scribble session API (tldraw `editor.scribbles.startSession`).
- Sidebar-to-canvas drag creation (X6 Stencil, GoJS Palette) as the reference shape if an authoring preset is ever built on `addNode`.
- Contextual per-node action surfaces: NodeToolbar (React Flow) and the bpmn-js context pad, both of which need only a stable anchored-overlay primitive.
- `%%{init: {...}}%%` single front-matter config block (mermaid) and D2's numbered theme catalog, as lighter entry points than hand-tuning custom properties.
- Compass-point port syntax `n/ne/e/se/s/sw/w/nw/c` (Graphviz) as a familiar vocabulary if ports are ever added, and color-coded socket types (Blender) as the cheap visual half of typed ports.
- Cascading filter pipelines where each filter applies to the previous result (Gephi Lite), and categories plus auto-legend plus click-to-toggle (ECharts).
- Sampling helpers that return only on-screen elements for overlay placement, e.g. `getSampledLinks()` (Cosmograph), which pairs naturally with viewport culling.
- Queued calls until ready: a promise-gated `graph.ready` so early API calls buffer instead of failing (Cosmograph), a good analog for font loading in record mode.
- Buffered relay with replay for late-connecting clients (`@statelyai/inspect`), the shape a shared or remote replay viewer would take on top of `run.log()`.
- Model-as-code with multi-target export from one source (Structurizr DSL), and draw.io's `postMessage` init/load/save/exit handshake if a sandboxed embed is ever needed.
- Distributing the model, the renderer and the algorithms as separate installable packages (graphology, sigma, graphology-*), which validates the satellite-subpath pattern already used for `export` and `a11y-table`.
- Disabling structural interaction while a simulation plays (bpmn-js token simulation), a small safety behavior worth copying during Mode A playback.
- Naming precedent for grouping and rollup: G6 "combo" and ComboCombined for container-scoped layout, Argo's template-ref grouping for repeated invocations.

## Prioritized recommendations

Ordered by leverage per unit of effort against the library's stated remit (an embeddable, zero-build, narration-first animated pipeline visualizer). Effort is rough: small is days, medium is a week or two, large is a milestone.

### In remit, do next

1. **Pointer events on nodes and edges, plus a selection set.** Unlocks the tooltip, context-menu, search, drill-down, explorable-figure and collapse-from-selection gaps and roughly a third of the use-cases above. Effort: small. Fit: add `nodeclick`, `nodeenter`, `nodeleave`, `edgeclick` (and their edge equivalents) to `GraphEventMap` with a `{id, data, event}` payload, gated by a mount option such as `interaction: {pointerEvents: true}`; add `g.select(ids)` writing `data-selected` so CSS and presets can react. Nothing about the render or animation loop changes.
2. **A live text and number channel on nodes and edges.** Unlocks the largest cross-cutting need (elapsed timers, counts, throughput, queue depth, cost, "142/180") named by seven perspectives. Effort: medium. Fit: `g.text(id, {sub, badge})` and an equivalent for edges, written into a dedicated secondary text element that is excluded from box measurement so updates never trigger a relayout, plus a documented recipe for binding it to `run` events.
3. **A tooltip preset shipped as a separate subpath export.** Unlocks the most-cited missing affordance without growing the core bundle. Effort: small. Fit: `sparkle-motion-visualizer/preset-tooltip`, following the `preset-pipeline` contract `(g, opts) => ({destroy})`, built on recommendation 1 plus `viewport.worldToScreen`, positioned on each commit and tick, using the native Popover API with no dependency.
4. **An analysis subpath of pure functions over `g.spec()` and the compiled schedule.** Unlocks blast radius, affected sets, critical path, cycle listing and highlight targets, which today every consumer recomputes. Effort: small to medium. Fit: `sparkle-motion-visualizer/analysis` exporting `reachable(spec, id, {direction})`, `pathBetween`, `criticalPath(spec | sim)` and `cycles(spec)`, all returning id arrays that feed straight into `g.highlight()` and `g.camera()`, kept out of the IIFE exactly like `export` and `a11y-table`.
5. **Importers, starting with Graphviz DOT and a generic event-log mapper.** Unlocks the single largest structural gap: every use-case currently begins with a bespoke adapter. Effort: medium. Fit: `sparkle-motion-visualizer/import-dot` returning a `GraphSpec`, and `sparkle-motion-visualizer/import-log` mapping a `{case, activity, timestamp}` or `{id, phase, at}` shape onto Mode B `run.start/finish/fail/spawn` calls. Add OTLP traces next, since three perspectives asked for it independently.
6. **Director ops and recording over finite, already-collected Mode B logs, plus a log-to-schedule bridge.** Unlocks postmortems, incident replays, trace explainers and every "narrate the real run" case, which are currently locked out of captions, camera and video entirely. Effort: medium to large. Fit: keep the refusal for a live, still-growing frontier, but allow `camera`, `highlight`, `caption` and `props` ops over a run whose log is closed (its total duration is then known and priceable), and add `compileLog(log) => sim` so `smv-record`, `g.cues()` and `smv-fit` apply unchanged.
7. **Minimap preset and a small viewport toolbar.** Unlocks the wayfinding gap named by nine cohorts and six use-cases, and the "no discoverable reset or download" complaint on embeds. Effort: small. Fit: two presets on the existing contract, drawing a scaled secondary SVG from `g.bounds()` and `g.layoutResult()` with a rect driven by `viewport.screenToWorld`, and buttons calling `fitView()`, `viewport.zoomBy()` and (in ESM builds) `exportPNG()`.
8. **Render-time fan-out of coincident parallel edges, behind a routing option.** Unlocks a documented regression versus dagre that breaks state machines, protocol animations, architecture reviews and any multi-relationship graph. Effort: medium. Fit: a mount option `layout.edgeRouting: 'polyline' | 'orthogonal' | 'smooth'` consumed in `src/path.js` only, with a perpendicular offset per duplicate `(source, target)` pair at draw time, leaving `src/engine.js` ranking untouched (the deviations note already identifies this as a rendering concern).
9. **Session snapshot and deep links.** Unlocks save/resume, shareable views, bug reports, chapter links from docs, and comments that point at an instant. Effort: small. Fit: `g.snapshot()` returning `{spec, viewport, theme, collapsed, emphasis, time}` and `mount(el, snapshot)` accepting it, plus a documented `toQueryString`/`fromQueryString` helper and a storyboard label hash convention.
10. **A temporal layout solver behind the existing seam, with a wall-clock readout.** Unlocks the most-repeated capability gap in the report (six of eight perspectives) and the deferred item in `docs/DEVIATIONS.md:273`. Effort: large. Fit: `sparkle-motion-visualizer/adapters/temporal` implementing `LayoutSolver` with x derived from `data.duration` or from `run.spans()` and y from a lane key, plus an `origin` mount option so the scrubber and captions can display absolute timestamps. Ship `run.spans()` first: it is small, independently useful for tooltips and exports, and is the prerequisite.

### In remit, later

11. **Node icon slot and a small shape vocabulary.** Unlocks the highest-fit rendering gap (icons) for architecture, integration, agent and infrastructure diagrams. Effort: medium. Fit: an optional `node.data.icon` (symbol id or data URI) rendered as an `<image>` or `<use>` inside the existing rect, and an optional `node.data.shape` limited to a fixed set (rect, diamond, cylinder, circle) so measurement, culling and theming stay deterministic. Not `foreignObject`, which would break export and recording.
12. **A React wrapper as a separate package.** Unlocks adoption in the surfaces where the audience actually lives (CI dashboards, docs sites, ops consoles) without touching the framework-free core. Effort: small. Fit: a thin component calling `mount`/`destroy` in effects, forwarding `spec` and `opts` as props with a diff into `g.update()`, published alongside rather than inside the core package.
13. **Streaming transport helper with reconnect, backfill and log windowing.** Unlocks every live board and monitor, and fixes unbounded log growth on panels that run for days. Effort: medium. Fit: `sparkle-motion-visualizer/adapters/stream` taking an `EventSource` or `WebSocket` plus a field mapping, replaying from `run.log()` on reconnect, and a `run.truncateBefore(t)` operation on the run controller.
14. **Recording and packaging polish.** Unlocks the narrated-video use-cases that currently need a manual ffmpeg step or a second tool. Effort: medium. Fit: `smv-record --audio track.wav` (ffmpeg is already a dependency of `--out`), `--preset 16:9|9:16|1:1`, `--stills` emitting one frame per storyboard label, `--pdf` via Chromium `page.pdf()`, `smv-fit` learning to price `run.play` and to compress as well as stretch, and `smv-pack --vars` for templated per-audience specs.
15. **Simulation semantics: exclusive and probabilistic routing, token identity, node capacity.** Unlocks Petri nets, statechart guards, DES, funnels, supply chains and capacity reviews, that is, most of two whole perspectives. Effort: large. Fit: `edge.data.p` or `edge.data.choice` honored by the compiler as an exclusive split, `spawn(id, n, {class, label})` giving tokens a class rendered as a color or glyph, and `node.data.capacity` with a queued-versus-in-service distinction surfaced as new run statuses. Sequence this behind the time-axis work, since a queue that is not visible on a time axis is only half legible.

### Out of scope, say no

- **Interactive graph editing** (node dragging, edge drawing, resize handles, stencil palettes, snaplines, clipboard, undo/redo as an editor history). This is the largest single cluster of gaps in the catalogue and the one to decline most firmly: computed layout is what makes order stability and byte-identical recording possible, and `docs/PLAN.md:32` already excludes it. If a consumer needs an editor, the correct answer is that they need a different library. The narrow exception worth reconsidering later is an opt-in position pin fed back into the solver as a constraint, and only if constraint layout is built for other reasons.
- **Force-directed and physics layout in the core.** Explicitly rejected in `docs/research/critique.md:143` for undermining determinism, and rightly. If someone wants it, it belongs in a third-party `LayoutSolver` adapter, not in `src/engine.js` and not in the default bundle.
- **WebGL or Canvas rendering, and 3D.** The CSS-custom-property styling model, the DOM accessibility tree, the SVG export path and the CSS-driven theming all depend on SVG being the document. A second backend would fork every one of those. Say the ceiling out loud instead: this library targets hundreds of elements with culling, not tens of thousands, and sigma.js, Cosmograph and G6 exist for that.
- **Real-time collaboration and viewer analytics.** Both require a server, an account model and a shared mutable document. A client-side embeddable library with no backend cannot own them, and adding them would change what the project is.
- **Other diagram families** (sequence diagrams, UML, mindmaps, ER and `sql_table`, Salt wireframes, multi-series chart composition). These are different product categories that mermaid, PlantUML, D2 and ECharts already serve well.
- **A text DSL as the primary authoring format.** Already decided in `docs/research/api.md:40`. An optional third-party compiler that emits a `GraphSpec` is welcome; it should not become the spec.
- **Multi-run analytics** (backfill grids, duration and flakiness trends, fleet dashboards, run history storage). These need persisted run history and are an observability product's job. The library's contribution is to render one run well and to expose `run.log()` so someone else can aggregate.
- **Graph-theoretic analysis at library scale** (centrality, community detection, clustering) beyond the path and reachability work in recommendation 4. If it is ever wanted, it goes in the same optional `analysis` subpath and never in the core bundle.
